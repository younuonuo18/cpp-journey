# W01 提示词记录（教材 1.5 用）

> 教材要求：提示词要记下来，第 10 章还要用。这里存**原始版**，不美化、不事后加工。

## 第 1 步 · 需求分析（发给 AI 之前，我自己写的）

- 输入：输入两个数字，交互输入
- 输出：两个数相加所得的和
- 边界：正数范围内

## 提示词 1 · 第一版（朴素版）

**日期**：2026-10-01
**原文**：
> 输入两个数字（交互输入），输出两个数相加所得的和，边界在正数范围内。

**AI 输出**：见下方「第一版代码」

**第 4 步 代码校验记录**：
- [x] 自己通读一遍
- [x] 编译 → **第一次失败**：`error C4996: 'scanf': This function or variable may be unsafe`（VS 控制台模板默认开 SDL 检查，AI 没考虑本机编译选项）→ 加 `#define _CRT_SECURE_NO_WARNINGS` 后通过
- [x] 逐行加中文注释
- [x] 测 4 组边界（结果见下方对比表）→ 发现 3 个问题

### 第一版代码（原始 AI 输出，仅加了一行本机必需的宏）

```c
#define _CRT_SECURE_NO_WARNINGS

#include <stdio.h>

int main(void)
{
    int a, b;

    printf("请输入第一个数：");
    scanf("%d", &a);

    printf("请输入第二个数：");
    scanf("%d", &b);

    printf("两数之和：%d\n", a + b);

    return 0;
}
```

## 提示词 2 · 迭代版

**原文**：
> 请增加输入校验和溢出检查：只接受正整数；输入不是数字时要提示；两数之和超出 int 范围要拦住并说明原因。

**AI 输出**：`w01-hello/01/sum.c`（当前版本）

**这版比第一版多了三件事**：
1. **输入校验**——判断 `scanf` 的返回值，挡住非数字输入
2. **边界校验**——只接受正整数（兑现需求里"正数范围内"这句话）
3. **溢出检查**——`a > INT_MAX - b` 提前拦住，而不是让它静默算成负数

## 两版差异 · 同一套输入的实测对比

| # | 输入 | 第一版（朴素） | 第二版（迭代） |
|---|---|---|---|
| 1 | `3` / `5` | `8`（退出码 0） | `8`（退出码 0） |
| 2 | `-2` / `7` | `5` ← **"正数范围内"完全没拦** | 报错「只接受正整数，收到 -2 和 7」（退出码 1） |
| 3 | `2147483647` / `1` | **`-2147483648`** ← 静默溢出 | 报错「两数之和超出 int 范围」（退出码 1） |
| 4 | `abc` / `5` | **`-1717986920`** ← scanf 失败，变量未初始化 → 垃圾值 | 报错「输入无效：请输入整数」（退出码 1） |
| 5 | `999999999` / `1` | `1000000000` | `1000000000`（确认校验没有误杀） |

## 结论：哪一版更好？为什么？

**第二版更好，但不是因为它"更聪明"**——而是因为我的第二条提示词把三类约束**显式写出来**了：

1. **合法性**：输入必须是数字（第一版压根不管，`scanf` 失败也不吭声）
2. **边界**：必须是正整数（第一版把需求里的"正数范围内"当成了摆设）
3. **值域**：和不能超出 `int`（第一版静默溢出成负数——**这类 bug 最危险：不崩溃、不报错，只是算错**）

一句话：**第一版缺的不是能力，是我没说的约束。** AI 只会照你说的做，不会替你补全需求里没想到的部分——所以"需求分析"和"迭代优化"这两步，才是人不能省的部分。

## 本次真正卡住的两个点（环境相关，以后还会遇到）

1. **AI 给错了语言**：第一次要代码时提示词没指定语言，Copilot 给了 **C#**（`using System; class Program; static void Main`），粘进 `.cpp` 直接 5 条编译错误。留档：`w01-hello/01/failed-csharp-attempt.cpp.bak`。
2. **AI 的代码在本机编译不过**：标准 C 的 `scanf` 被 VS 模板的 SDL 检查当错误（C4996）。这种"AI 不考虑你的编译环境"的问题，**只有真编译一次才会暴露**——这就是第 4 步「代码校验」绝不能被跳过的原因。
