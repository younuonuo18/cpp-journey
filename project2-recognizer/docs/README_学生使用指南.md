# 《高级语言程序设计》实验资源：小型静态特征识别器（学生版）

## 0. 安全边界与学习目标

本次实验**只使用CSV中的人工构造静态特征数值**，不收集、下载、运行或传播真实恶意代码。程序输出的`良性/可疑`仅是教学模型对构造数据的类别预测，不应作为真实软件的安全判定。

面向低年级学生的目标：O1 C语言数据处理，O2 简单分类原型集成，O3 AI辅助方案及代码审查，O4 安全规范和工程责任。

## 1. 建议在16学时内完成

1. **2学时：** 理解数据、独立列出功能需求，使用大模型比较模块划分并解释取舍。
2. **6学时：** 完成CSV读取、结构体与数据校验函数；用异常文件进行单元测试。
3. **4学时：** 读取参考模型、保持训练/预测的归一化规则一致、完成菜单与预测输出。独立训练和评估为进阶任务。
4. **4学时：** 至少修复一个典型错误案例，提交“AI建议—程序诊断—修正—回归测试”的证据链。

## 2. 数据概览

| 文件 | 条数 | 含标签 | 用法 |
| --- | ---: | --- | --- |
| `data/sample.csv` | 8 | 是 | 格式讲解与程序最小验证，**不是测评集** |
| `data/train.csv` | 160 | 是 | 训练模型、计算scaler |
| `data/test.csv` | 60 | 是 | 独立测试、分类指标计算 |
| `data/predict.csv` | 20 | 否 | 模拟新样本的预测 |
| `data/invalid/` | 18份CSV与1份坏模型 | 视测试而定 | 检查非法值、异常处理和极端输入 |
| `sample_expected.csv` | 8 | 预测对照 | 用提供的`reference_model.txt`可复现 |

CSV列顺序必须固定：

```
file_size,string_count,entropy,byte_00_ratio,byte_ff_ratio,label
```

预测数据`predict.csv`没有`label`列。`file_size`须非负、`string_count`须为非负整数、熵值须在0至8之间，两个比例值须在0至1之间，标签只能是0或1。

参考模型文件`reference_model.txt`提供5个权重、一个偏置以及五维特征对应的归一化`min`与`max`，具体格式见`docs/模型文件说明.md`。同一个模型在训练、预测和保存/加载后必须使用同一组归一化参数。

## 3. C语言骨架使用方法

`starter/recognizer_starter.c`是**故意未完成但可以编译**的项目骨架。TODO函数将返回“尚未实现”，这不是可以直接提交的完整识别器。

**GCC：**

```bash
cd starter
make
./recognizer_starter
```

没有Make工具时可直接执行：

```bash
gcc -std=c11 -O2 -Wall -Wextra -pedantic recognizer_starter.c -lm -o recognizer_starter
```

在Visual Studio等开发环境可将`recognizer_starter.c`新建为C项目并链接数学库；开发时保留必要的错误处理和边界检查。

## 4. 两个错误诊断案例

`examples/bug_case_A.c`故意把比例特征下标写错，导致不合法的`byte_ff_ratio`通过检验。

`examples/bug_case_B.c`故意只保存权重和偏置、未保存训练集归一化参数，展示重新加载后同样输入的预测值为何变化。

示例可以独立编译；**它们是刻意植入错误的教学材料**，不要直接复制到最终项目。提交时至少完成其中一个的复现、定位、修正和回归测试。

## 5. 大模型协作记录要求

每位学生至少3次保留有代表性的记录，覆盖：需求/方案、代码理解/实现、调试/测试。记录原始提示词、模型建议、采纳/修改/拒绝原因和人工验证证据。课题组可以选用任一合规的大模型，不应提交只有AI生成而自己无法解释的完整程序。
