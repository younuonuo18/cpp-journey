## 一、AI 交互记录编号与提示词（记录 3 · 调试与测试验证）

**原始提示词**（我实际发出的）：

> 教师给的教学案例 `bug_case_A.c` 里有一段 AI 候选校验代码 `validate_buggy()`，注释说"features[2] is entropy, and features[4] is left unchecked"。
> 我的项目里特征下标约定是：0=file_size、1=string_count、2=entropy、3=byte_00_ratio、4=byte_ff_ratio；
> 其中 entropy 合法区间是 [0,8]，两个比例是 [0,1]。
> 请先不要重写我的整个程序，只回答三件事：
> ① 这段代码具体错在哪几个下标上；② 它会造成哪两类后果（不只是"该拦的没拦"）；
> ③ 我应该补哪些检查，才能同时通过 T04/T05/T08/T12/T14 这些异常用例，并且不误杀 T17 这种合法边界值？

**AI 建议摘要**：指出 ① `features[2]` 是 entropy 却按 [0,1] 检查、`features[3]` 是 byte_00_ratio 被正确检查、**`features[4]`（byte_ff_ratio）完全没检查**；② 后果有两类：**漏放**（`byte_ff_ratio=1.3` 被接受）和**误杀**（`entropy=8`、`entropy=5.92` 这类合法数据被当成越界拒绝）；③ 建议按字段逐项补全 file_size ≥ 0、string_count 非负整数、entropy ∈ [0,8]、两个比例 ∈ [0,1]。

## 二、错误发生条件及现象（可复现）

**发生条件**：把教师案例 `examples/bug_case_A.c` 按原样编译运行（本机用 VS 2026，`Debug|x64`）。

**现象（案例原始输出）**：

```text
buggy_result=0; correct_result=3 (invalid byte_ff_ratio)
Task: inspect features[3]/[4], fix the check, rerun tests.
```

`buggy_result=0` 表示"**校验通过**"——但输入的 `byte_ff_ratio = 1.3` 明显超出 [0,1]，**应该被判为非法（返回 3）**。案例里故意把 `entropy` 设成 0.5（落在 [0,1] 之内），就是为了让"下标用错"这个缺陷暴露出来。

**我构造的复现输入**（放进回归测试用例①）：

```c
Sample s = { {8192, 42, 0.5, 0.2, 1.3}, 1 };   /* features[4] = byte_ff_ratio = 1.3 非法 */
```

## 三、原始（AI 候选）代码片段

```c
int validate_buggy(const Sample *s)
{
    if (s->label != 0 && s->label != 1) return 2;

    /* BUG：features[2] 是 entropy（合法区间是 [0,8]，不是 [0,1]），
     *      而真正的 byte_ff_ratio（features[4]）根本没有被检查。 */
    if (s->features[2] < 0 || s->features[2] > 1 ||
        s->features[3] < 0 || s->features[3] > 1) return 3;

    return 0;
}
```

## 四、人工定位依据（不依赖 AI 的独立判断）

1. **对照字段—下标对照表**（教师《模型文件说明》与本项目 README 都写明）：

   | 下标 | 字段 | 合法区间 |
   |---|---|---|
   | 0 | file_size | ≥ 0 |
   | 1 | string_count | ≥ 0 的整数 |
   | 2 | **entropy** | **[0, 8]** |
   | 3 | **byte_00_ratio** | [0, 1] |
   | 4 | **byte_ff_ratio** | [0, 1] |

2. **逐行核对该函数实际检查了哪些下标**：只出现 `features[2]` 与 `features[3]` → **`features[4]` 从未出现**（漏检）；而 `features[2]` 用的上界是 `1`，与 entropy 的 `8` 不符（**区间用错**）。
3. **用反例验证**：用最小输入 `{8192, 42, 0.5, 0.2, 1.3}` 运行，得到 `0`（通过）→ 证明缺陷真实存在，而不是"看起来可疑"。
4. **反向验证（误杀）**：用合法数据 `{100, 3, 8, 1, 0}`（T17 边界，entropy = 8）运行原实现 → 得到 `3`（被拒绝）→ 说明该缺陷**还会把合法样本挡在门外**。这一步是 AI 最初只说了"漏检"、由我在测试中补上的。

## 五、修正方法与代码

**修正点（4 处）**：① entropy 改用 [0,8]；② 真正检查 `features[4]`；③ 补 file_size ≥ 0；④ 补 string_count 非负整数。

```diff
 int validate_fixed(const Sample *s)
 {
     if (s->label != 0 && s->label != 1) return 2;
-    if (s->features[2] < 0 || s->features[2] > 1 ||
-        s->features[3] < 0 || s->features[3] > 1) return 3;
+
+    if (s->features[0] < 0.0) return 3;                                  /* file_size ≥ 0 */
+    if (s->features[1] < 0.0 ||
+        s->features[1] != floor(s->features[1])) return 3;                /* string_count 非负整数 */
+    if (s->features[2] < 0.0 || s->features[2] > 8.0) return 3;           /* entropy ∈ [0,8] */
+    if (s->features[3] < 0.0 || s->features[3] > 1.0) return 3;           /* byte_00_ratio ∈ [0,1] */
+    if (s->features[4] < 0.0 || s->features[4] > 1.0) return 3;           /* byte_ff_ratio ∈ [0,1] */
+
     return 0;
 }
```

完整可编译代码：`src/bug_case_A_fixed.c`（同一个文件里保留"错误版"与"修正版"，便于对照与回归）。
